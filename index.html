The missing link

No publicly available dataset exists for Phosphorus deficiency in tomato leaves. No existing system combines nutrient deficiency detection, co-occurrence-aware disease detection, treatment monitoring, and market price forecasting in one platform for Sri Lankan farmers. TomatoDoc addresses all four problems together.

The question TomatoDoc answers

Sri Lankan tomato farmers have no affordable, accessible tool that can diagnose plant health problems from a smartphone photograph, track whether treatment is working, and advise when to sell their harvest for maximum profit – all in one place.

Component 2 – Leaf Disease Detection with Co-occurrence Awareness

Early Blight, Late Blight, and leaf miner damage can appear on the same tomato leaf, but most tools return a single label and give treatment advice that is not linked to a verified source.

  1. Detect six tomato leaf nutrient deficiency classes using MobileNetV2 Transfer Learning with 93 percent or higher test accuracy.
  2. Detect and localise Early Blight, Late Blight, and Leaf Miner symptoms on tomato leaves using YOLOv8s, report several conditions for one leaf, and recommend treatment from verified agricultural sources.
  3. Monitor seven-day treatment response using U-Net pixel-level severity segmentation and classify treatment outcome.
  4. Forecast wholesale tomato market prices across 1 to 14-day horizons using Direct Multi-Output BiLSTM, LSTM, and XGBoost corroborated with agro-meteorological features and SHAP-based explainable recommendations.

Component-wise objectives

Component 2 – Leaf Disease Detection with Co-occurrence Awareness

A.L.M. Farthas (IT22190734)

Main objective

Detect and localise Early Blight, Late Blight, and Leaf Miner symptoms on tomato leaves, so that several conditions can be reported for one leaf, and recommend treatment from verified agricultural sources.

Sub-objectives

  • Build a symptom-level, four-class leaf dataset (Early Blight, Late Blight, Leaf Miner, Healthy).
  • Train YOLOv8 variants, compare them on the validation set, and select the model for deployment.
  • Evaluate detection with precision, recall, F1, and mAP, overall and for each class.
  • Generate treatment advice from a curated, source-tagged knowledge base using retrieval-augmented generation.
  • Deploy the detector and advice service as a cloud API used by the mobile application.

Novelty

Each symptom is localised with its own bounding box, so several conditions can be shown on one leaf without training images labelled with disease combinations. Treatment advice is retrieved from named agricultural sources (Department of Agriculture Sri Lanka, peer-reviewed studies, and extension guidance) and states when guidance is general.

  1. 01Dataset Collection
    Collected tomato leaf nutrient deficiency and fruit disease images from public agricultural datasets.
  2. 02Data Preprocessing
    Split datasets before augmentation and applied image transformations to training data only.
  3. 03Model Training
    Compared CNN Scratch, VGG16, ResNet50, and MobileNetV2 before selecting the mobile-friendly model.
  4. 04Object Detection
    Trained YOLOv8 variants on a symptom-level, four-class leaf dataset, compared on the validation set, and selected YOLOv8s. Each symptom is reported with its own bounding box, so Early Blight, Late Blight, and Leaf Miner can be shown together on one leaf.
  5. 05Treatment Monitoring
    Used U-Net segmentation to estimate disease severity across a seven-day monitoring window.
  6. 06Price Forecasting Pipeline
    Harmonized multi-year wholesale price indices from Sri Lankan DECs synchronized with Open-Meteo meteorological indicators. Trained SARIMA, Random Forest, XGBoost, GRU, and Direct Multi-Output BiLSTM models using walk-forward validation and SHAP explainability.
  7. 07RAG System
    Connected ChromaDB to a hosted language model (Groq Llama for Component 1, Gemini for Component 2) to generate treatment advice grounded in agricultural guidelines.
  8. 08Mobile Application
    Integrated all AI components through Flask and FastAPI APIs in a React Native application.

Component methodologies

Component 2 – Leaf Disease Detection with Co-occurrence Awareness

1
Data

Collected tomato leaf images from public sources, annotated symptoms with bounding boxes (leaf miner re-annotated at tunnel level), removed duplicate images, and split the data 80/10/10 into training, validation, and test sets.

2
Model

Trained YOLOv8n, YOLOv8s, and YOLOv8m under identical settings from COCO-pretrained weights, compared them on the validation set, and selected YOLOv8s.

3
Evaluation

Reported precision, recall, F1, and mAP overall and per class on the test split, with a confusion analysis of missed detections.

4
Treatment advice

Built a source-tagged knowledge base, embedded it with a sentence-embedding model into ChromaDB, and used a Gemini model restricted to the retrieved text to write the advice.

5
Deployment

Packaged the detector and advice service with Docker on Google Cloud Run and connected it to the React Native mobile application.

    01 / The idea

    About TomatoDoc

    TomatoDoc is a four-component AI mobile application for Sri Lankan tomato farmers, connecting nutrient diagnosis, disease detection, treatment monitoring, and price forecasting in one accessible workflow.

    🌿
    COMPONENT 01

    Nutrient Deficiency Detection

    MobileNetV2 transfer learning model that detects six types of tomato leaf nutrient deficiency from a smartphone photograph.

    🍅
    COMPONENT 02

    Fruit Disease Detection

    Second MobileNetV2 model that detects five fruit disease classes from tomato fruit photographs.

    🔍
    COMPONENT 03

    Leaf Disease Detection with Co-occurrence Awareness

    YOLOv8s model that localises Early Blight, Late Blight, and Leaf Miner symptoms at lesion level for one or several conditions per leaf.

    📈
    COMPONENT 04

    Treatment Efficacy Monitoring

    U-Net semantic segmentation model that tracks disease severity as a pixel percentage over a seven-day treatment window.

    💰
    COMPONENT 05

    Market Price Forecasting

    Direct Multi-Output Bidirectional LSTM provides multi-horizon price projections and SHAP-based explainability.
